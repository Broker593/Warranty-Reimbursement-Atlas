# Editing this project

- GitHub Pages serves `docs/` from `main`. Committed updates publish automatically after deployment succeeds.
- Use this repository as the shared source of truth; inspect current files before editing because other assistants may change them.
- Do not invent reimbursement rates. This project summarizes public legal methods, not any company's approved rates. Never name a specific manufacturer or company in site text.
- Keep original-source availability distinct from summary verification. Preserve publisher and source-date information.
- Check current official statutes for legal changes and link the exact provision. An accessible statute alone does not justify upgrading verification status.
- Maintain state conditions, elections, exclusions and passenger-vehicle scope. Check that checkbox classifications agree with state narratives.
- If coverage changes, update the coverage statements in `docs/index.html` and README.md.
- Static site, no build needed. For JavaScript edits run `node --check` on `docs/data.js`, `docs/coverage-data.js`, `docs/coverage.js` and `docs/extras.js`; verify affected interactions when a browser is available.
- The older ChatGPT Sites deployment is independent. Do not claim it auto-syncs with GitHub.
- The site (States home, state pages, Summary dashboard, News, Downloads, Update log) renders through `docs/extras.js` from `docs/data/*.json` (audit fields, key facts, weekly checks, news) plus `docs/data.js` and `docs/coverage.js`. Run `node --check docs/extras.js` after edits.
- `docs/data/audit-procedures.json` (50-state audit/chargeback procedures), `docs/data/flagged-states.json` (flagged states, labeled Flagged only), `docs/data/cases.json` (key cases and laws) and `docs/data/audit-index.json` (audit climate scores, generated by `tools/audit_index.py`; never hand-edit. Method: each limit gets a level 0–3 read from the research; weights live only in `FACTORS` in that script and add up to 100. A partial limit may be recorded in audit-procedures.json with `score_level` (0–3) plus a written `score_level_reason`) feed the state pages, Map: U.S. Audit Climate and Cases & laws tabs. Keep distributor and index wording neutral: statute facts only, no company-specific audit strategy.
- Audit briefs (`docs/data/audit-brief/index.json` plus one `XX.json` per state; four states so far: FL, CA, IL, AR). The brief is what an auditor needs before auditing a dealer's paid factory-warranty claims, in the order an audit runs: five sections (audit eligibility, planning restrictions, testing and findings, chargeback process, exceptions and escalation). It renders at the top of the state page (above Key facts; the audit climate score is collapsed below it) as the same summary table as page 1 of the PDF, with the full lines, statute quotes and legal-review blocks in a notes fold under it and as a two-page PDF at `docs/downloads/audit-briefs/XX-audit-brief-<verified date>.pdf` (page 1: at-a-glance table whose rows come from `glance_rows` in index.json and each rule's `glance` line of a dozen words; page 2: numbered notes with the full `short` lines, legal-review items, topics not addressed, penalties and forum) (built by `tools/build_exports.py`; the file name carries the verification date so superseded copies are identifiable, and older files are removed from the folder on build; git history keeps them). Each rule carries `effect` (required | prohibited | permitted | conditional | not_expressly_addressed), `status` (express | reasoned_interpretation | conflict | unresolved, with a `reason` unless express), `covers` (programs), `pinpoint`, `pin_short`, `url`, a verbatim `quote` (40 words max) and `value` (full answer). Rules with `brief: true` and a `short` line appear on the PDF notes page and the main block (a rule named in `glance_rows` also needs a `glance`); the rest are web-only under "Other topics reviewed". Never infer whole-claim recovery or permission from silence: silence is `not_expressly_addressed`, listed in `not_addressed` with the sections reviewed. Any rule with status conflict or unresolved must have a matching `legal_review` entry (title, one-sentence `summary` for the PDF, full `text`, `action`, pinpoint, quotes); it renders as a LEGAL REVIEW REQUIRED block until the data records a resolution. Keep `penalties_line` and `protest_forum` as the closing lines. Follow `tools/AUDIT_BRIEF_PLAN.md`; the research pass per state (structured validation of the existing fields plus an open-ended exception search) is recorded in `docs/research/audit-brief/XX-research-<date>.json`. `tools/check_consistency.py` (check 13) validates the files and that the brief's audit window agrees with `audit-fields` lookback. Adding a state: write `XX.json`, add it to `index.json` with its verified date and PDF path, run the build.
- `docs/data/key-facts.json` holds the short labels on the States table. Keep each label a faithful summary of the underlying record; when enacted law changes a rule, update the record and the label together.
- After any data change run `python3 tools/build_exports.py` so the Excel and PDF downloads match the site. Each state PDF must stay one page.
- The Monday weekly check follows `tools/WEEKLY_CHECK.md`. Never load pending bills as enacted law.
- Second opinion before substantive changes. Before changing how a rule is read (statute research, new data fields, the scoring method) or the site's structure (new sections, redesigns), send the proposed approach, with the relevant statute text, to ChatGPT in the "Warranty Atlas Review" chat (started 2026-10-22; the pinned "Warranty Atlas" build chat has a hung run from Sept 29 and branches, so don't use it for reviews) and ask for a critique. Open each review with a short recap of the site's current state. Type messages without newlines: Enter sends. Publishing stays in the separate "Publish atlas build" chat. Answer its points and go back and forth, up to three rounds, until both agree on the approach; if they still disagree, write both positions down for Dave to decide. Treat its feedback as input, not a verdict: verify every cited statute passage before adopting it, and never let a reviewer's unverified claim into the data. Routine edits (labels, layout fixes, the Monday weekly check) skip this step.
- Link previews: `docs/index.html` has Open Graph tags with absolute URLs to `docs/og-card.png` (1200×630, brand mark centered so a square crop still works) and icons in `docs/icons/`. If the site moves to a custom domain, update those URLs and the hostname check in the analytics snippet.
- `docs/index.html` loads Google Analytics 4 (measurement ID in the first `<script>` block) and the footer and About dialog disclose it with an opt-out. Keep all three. Page views are sent from `track()` in `docs/extras.js` (one per tab or state page); do not add a second page-view source.
